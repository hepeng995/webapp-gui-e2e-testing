# 环境准备、预检与收尾（environment）

## 0. 模式自动推断（开工时执行）

环境模式（**本地环境 / 网络测试环境**）自动推断，判定优先级从高到低，命中即停：

1. **用户明示**：用户话中已说明"本地环境 / 网络环境 / 用测试环境地址 xxx"→ 直接采用，不算推断；
2. **被测 URL 的 host**：`localhost` / `127.0.0.1` / `[::1]` / 本机 hostname / 本机 IP → **本地环境**（服务未起也归本地环境，由 Agent 负责起）；其余域名或 IP（含局域网 192.168.x.x / 10.x，属他人部署）→ **网络测试环境**；
3. **未给 URL 但给了本地项目代码路径**（或要求"把项目跑起来测"）→ **本地环境**；
4. **URL 与项目代码都没有** → 向用户要被测地址（唯一因缺输入而询问的场景）；
5. **混合信号**（如同时给 localhost 前端与远程后端地址）：以**被测前端 URL** 定模式，后端地址作为拓扑信息记录到环境说明。

推断结果与依据写入 `results/环境说明.md` 头部（例："环境模式：本地环境（自动推断：用户提供 URL host 为 127.0.0.1）"）。用户任何时候纠正即切换模式：环境说明追加变更记录，切换后重跑预检。

## 1. 环境模式

### 本地环境（Agent 搭建并管理全套服务）

Agent 负责本地起服务、配环境，对环境有完全控制权：

- **测试数据库**：新建独立库（命名带 `_test` 后缀，如 `app_e2e_20260908_test`）→ 按项目方式执行建库基线（schema/迁移脚本）→ 加载测试/演示 seed → **冒烟验证**：SELECT 关键表计数 > 0（防"执行无报错但数据静默丢失"）；
- **后端服务**：以测试库连接串启动到独立端口（如 3001），健康检查 200 并记录版本/commit；
- **前端服务**：起到独立端口（如 5189），API 代理指向自己的后端端口（临时代理配置收尾删除）；
- **测试对象形态**：优先测**生产构建产物**（build 后以静态/preview 服务提供），测得结论才对发布有效；用 dev server（热更新、sourcemap、代理行为可能不同）需在环境说明记录理由；
- **启动命令发现**：项目 AGENTS.md → `package.json` scripts → `Makefile` → `docker-compose`；中间件依赖（数据库/Redis/对象存储等）随主服务一并拉起（优先容器或项目自带脚本），过程记录到环境说明；
- **账号**：用 seed 账号或新建测试账号，逐个登录冒烟；
- **能力**：可执行破坏性用例（停后端/断网/错误态），数据最干净，可随时销库重建；
- **成本**：需要搭建时间；收尾必须完整清理（见 §5）。

### 网络测试环境（用户已部署，只提供地址与账号数据）

被测系统部署在远端/局域网，用户只需提供：**访问地址、账号凭据**，以及（可选）数据前缀与注意事项。Agent 的边界：

- **只接入，不搭建**：不起服务、不改服务端配置、不碰数据库（只读 SELECT 佐证仍允许）；
- **接入验证**：地址可达、健康检查 200、主测账号登录冒烟、记录版本/构建信息；
- **数据隔离**：本轮新建数据一律带统一前缀；不操作他人/存量数据；共享演示数据只读；
- **断言隔离**：全局计数只做差值断言（操作前后对比）；批量/导出类操作限定前缀筛选口径；
- **会话隔离**：必要时用不同 origin 或独立标签，避免与其他使用者会话互踩；
- **行为限制**：禁止停服务/断网/重启等破坏性操作，相关用例标 `SKIPPED-remote-env` 单列；
- **优点**：零搭建成本、贴近真实部署形态；**代价**：破坏性用例做不了、可能受同环境其他数据干扰。

## 2. 账号与凭据准备

- 每个角色账号先做**登录冒烟**（能登录、角色语义与矩阵一致），再开始执行；历史教训：seed 账号可能 password_hash 为空、账号类型被登录门禁拒绝、密码与文档不一致。
- 密码从环境负责人/部署配置获取，任何结果文件只写 `***`。
- **凭据保管协议**：凭据仅存在于会话内存与用户提供的配置源（环境变量/密码管理器/部署配置），全程不写入任何产出文件、summary、截图说明或日志；需要持久化时只记录引用（如"见部署配置 key x"）；一轮测试结束后会话中不再保留明文凭据。
- 需要新建测试账号时记录创建方式（UI/接口/seed），便于清理与复现。
- **账号来源（自动化优先）**：本地环境缺账号一律自行创建（seed / 注册接口 / UI 注册），只记录不询问；网络测试环境缺账号或凭据 → 向用户获取。
- **非常规登录处置**：图形/短信验证码、SSO/OAuth/扫码、2FA 等无法自动化登录时——本地环境改走可自动化的通道（如 seed 账号+密码登录）；网络测试环境请用户在浏览器手动登录一次，Agent 接管已登录会话继续执行，登录方式记录到环境说明。

## 3. 开工预检清单（全部通过并记录到环境说明后才开始）

| # | 检查项 | 方法 |
| --- | --- | --- |
| 1 | 端口空闲（本地环境：逐一探测，被占顺延；网络环境：不涉及） | 探测 |
| 2 | 前端可达 | 打开登录页，截图确认 |
| 3 | 后端健康 | 健康检查接口 200；核对返回的版本/commit（构建版本注入缺失要登记） |
| 4 | 数据库就绪 | 关键表存在；seed 数据 SELECT 计数 > 0 |
| 5 | 账号可登录 | 至少主测账号登录成功并核对权限入口 |
| 6 | 浏览器会话干净 | 清除残留 cookie/localStorage（历史教训：残留会话导致"未登录跳转"用例首测误判） |
| 7 | 网络断言通道 | 确认 ZCode 内置浏览器能观察网络请求与 console |
| 8 | 网络通道（网络测试环境） | VPN/代理可达（需 VPN 时先向用户确认接入方式）；自签证书告警、HTTPS 页面混合内容告警截图登记 |
| 9 | 后端健康降级 | 网络测试环境后端健康端点不公开时，降级为"前端可达 + 主测账号登录冒烟"，在环境说明注明 |

## 4. 环境说明文件

`results/环境说明.md` 记录：模式（本地/网络测试环境）、服务拓扑（地址/端口）、数据库与迁移/seed 版本（本地环境）、账号清单（脱敏）、网络环境的注意事项（其他使用者/数据口径）、预检结果。环境中途变更（换端口、重建库）必须追加记录。

## 5. 收尾清理（强制，无论测试通过/失败/中断）

1. 停止本轮拉起的所有服务进程（仅本地环境；网络测试环境无本地服务）；
2. 删除本轮创建的临时配置文件，如需保留逐个列出并说明原因；
3. 确认清理生效：目标端口已释放、相关进程已退出；
4. 测试数据**不强制清理**（本 skill 定位于开发环境自动化测试，数据可弃）；用户明确要求清理时才处理——本地环境销毁测试库，网络测试环境只清理本轮前缀数据且**不动环境本身**；
5. 无法自动清理的（端口被占、权限不足），在执行报告"残留"一节列出进程与处理建议。

## 6. 环境缺失自补充（授权 + 强制记录）

测试过程中发现缺少测试环境（缺账号、缺前置数据、缺配置、服务未起、缺 mock）时，允许自行补充：

1. **记录**：补充动作追加到环境说明（"自补充记录"节：时间、补了什么、方式、服务于哪些用例）+ 当日执行日报；
2. **不得替代被测行为**：补充只负责"让被测功能可达"，测创建流程不能直接插一条现成数据当结果；
3. **状态联动**：因补充解阻的用例（BLOCKED→可执行）在用例结果中注明"经环境补充后重测"；
4. **红线**：禁止为通过用例修改产品代码、禁止篡改数据库既有业务数据、禁止把缺陷现场"修好"（修复缺陷需用户授权，走 issue-tracking 流程）。

环境需求在开工时已按 `test-case-generation.md` §5 清单化（每项标注依赖用例），缺什么、影响面多大可直接对表判断。

清理证据写入执行报告"清理说明"一节。
