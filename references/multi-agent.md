# 多 Agent 并行测试协调（multi-agent，可选）

仅当用户要求多 Agent 并行测试同一应用时启用；单 Agent 忽略本文件。

## 1. 用例集隔离

- 每个 Agent 分配**零重叠**的用例集与功能域；任务书写明彼此范围，禁止执行对方归属用例。
- 归属有灰区时（如收尾回归涉及双方域）：允许重复执行无写入冲突的只读用例；写操作类灰区用例指定唯一归属方。

## 2. 数据前缀隔离

- 每个 Agent 独立数据前缀（`A1-` / `A2-` …），编号、标题、编码全部带前缀；
- 禁止操作对方前缀数据；共享演示基线数据双方只读，写操作各用前缀新建；
- 缺陷编号独立前缀：`BUG-A1-NNN` / `BUG-A2-NNN`，互不混号。

## 3. 端口与资源预分配

- 开工前分配各 Agent 独立的前端/后端端口，并逐一探测占用（其他本地服务进程可能占用）；被占时按预留序号顺延并互相同步。
- 共享模式下可用不同 origin（`localhost:PORT` vs `127.0.0.1:PORT`）隔离浏览器会话/存储。

## 4. 破坏性操作

- 网络测试环境禁止任何 Agent 停服务/断网/重启；本地环境各 Agent 使用独立环境（独立库+独立端口）随意，但端口仍按 §2 预分配。
- 影响对方的操作（大范围结构变更、共享账号改密）避免或协调时段。

## 5. 跨 Agent 依赖互通

一方用例依赖另一方产出的数据（如"订单物流跟踪区块"依赖对方先创建一笔已发货订单）时：

1. 需求方在执行日报中发出依赖请求（说明需要的数据、前缀、状态）；
2. 供给方完成产出后在日报中通报"可复测"；
3. 依赖未满足时用例标 `BLOCKED-dependency`，不算失败也不跳过登记。

## 6. 产出与汇总

- 各 Agent 独立产出目录（`agent1/`、`agent2/` …），结构一致，便于最终汇总；
- 测试全部结束后由牵头方合并：跨 Agent 问题去重（同一根因多 Agent 各记一条很常见）、合并缺陷清单、统一统计口径、产出总表（范围/结果/缺陷/环境差异/风险）。
