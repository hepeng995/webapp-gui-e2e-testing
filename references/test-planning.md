# 测试规划（test-planning）

按输入信息的完整度选择三条路径之一。产出一份"测试点清单"，后续执行循环按它逐条推进、勾选。

## 1. 路径 A：已有用例清单

1. 按顺序读：任务书/总体说明 → 用例清单 → 环境与账号章节 → 清单各条指向的断言依据（执行到哪条读哪章）。
2. 确认每条用例具备：编号、标题、断言依据（文档章节或预期结果）、优先级。缺失优先级的，按"涉及主流程/数据写入=P0，权限与边界=P1，配置与展示=P2"自行标注。
3. 把清单落为执行文件（复用 `assets/templates/case-result-template.md`），逐条勾选推进。
4. 逐字剧本类用例（编号 E2E-xxx 的端到端剧本）禁止跳步合并；每步断言逐条核对。
5. 已有权威清单时仍建议做一次**差异补全**（test-case-generation.md §7）：扫描代码与文档找清单未覆盖面，生成补充用例并展示摘要（非阻塞）。

## 2. 路径 B：无清单 → 生成用例文档（缺省主路径）

用户未提供用例清单时，按 `test-case-generation.md` 执行生成阶段：

1. 采集输入：项目代码（路由/API/数据模型/权限）+ 项目文档（PRD/API 文档/设计规范）；
2. 建立模块清单，按**十类测试**逐类生成用例（功能/UI-UX/兼容/性能/安全/接口/数据/异常/易用/回归）；
3. 汇总测试环境需求清单；
4. **展示用例摘要（非阻塞）**：简短罗列十类用例数量与覆盖面、待确认预期自动裁决结果，展示后直接进入环境准备与执行（test-case-generation.md §4；用户明说"先确认再跑"时才等待确认）。

## 3. 路径 C：轻量任务（单页面 / 单缺陷复现 / 快速冒烟）

范围很小、不值得生成完整用例文档时（如复现一个 bug、冒烟一个页面），先探索页面识别类型与功能区，按优先级生成测试点即可开始，全程自动执行不询问（环境模式自动推断，见 environment.md §0；唯一例外：用户标注被测对象涉及真实资金/生产数据时先问）：

| 级别 | 范围 | 示例 |
| --- | --- | --- |
| P0 主流程 | 核心功能的正常路径 | 提交表单成功、完成搜索、切换 tab、主链路端到端 |
| P1 交互反馈 | 操作后的反馈是否正确 | loading、成功/失败提示、按钮禁用、导航跳转、确认弹窗 |
| P2 输入边界 | 数据与输入的边界 | 空输入、超长输入、特殊字符、重复提交、非法格式 |
| P3 布局样式 | 视觉与渲染质量 | 遮挡、溢出、错位、对齐、空态缺失、徽章颜色 |

## 4. 路径 D：纯 URL 探索性测试（无代码、无文档，仅一个网址）

用户只给远端 URL（环境模式自动推断为网络测试环境）、无代码无文档无清单时走本路径。核心思想：**用系统化探索代替代码扫描**——探索过程本身就是用例来源。

1. **入口与账号确认**：打开 URL 截图确认可达；识别登录要求——需要账号而用户未提供 → 询问用户（自动化优先的唯一询问点）；无需登录直接开始。
2. **遍历式建树**：一次性爬取式遍历——逐菜单点开、逐 tab 切换、逐链接跟踪（限定同域），边探索边建 L1-L4 层级树，节点来源标"探索发现"；**遍历一遍即收束**，不为穷尽链接无限爬。
3. **测试点生成**：对探索到的每个功能区按 §3 的 P0-P3 + 覆盖维度矩阵（coverage-dimensions §1/§2/§3）生成测试点；预期按 test-case-generation.md §2 预期规则第 3 级（页面声明/惯例/全站一致性）确定。
4. **关联分析黑盒降级**：按 test-case-generation.md §2 关联分析的"纯 URL 黑盒降级"执行（网络观察推导 CRUD 矩阵与共享资源）。
5. **章程组织**（可选）：范围大时按 §5.2 一个章程一个时间盒，逐章程小结。
6. **产物**：测试点清单（路径 C 形态）+ 简化层级树 + 关联清单；执行循环、证据三件套、BUG 单流程与其他路径完全一致。

## 5. 启发式与回归圈定（路径 B/C/D 共用）

### 4.1 启发式扩展测试点

按 `coverage-dimensions.md` 的维度矩阵逐维度检查适用性，把缺测的维度补成测试点。12 条核心启发式速查：

| 启发式 | 要点 |
| --- | --- |
| 边界 Boundaries | 试 0、1、最大值、最大值+1 |
| 状态 States | 重复提交、后退、刷新、恢复保存的 URL |
| 角色 Roles | 对比 owner / member / 只读 / 无权 / 匿名的可见与可操作差异 |
| 数据形态 Data shape | Unicode、超长文本、空可选字段、时区、特殊字符 |
| 顺序 Sequence | 先 B 后 A、跳过 A、重复执行、双标签页同改 |
| 中断 Interruption | 网络失败、关标签页、会话过期、请求挂起时操作 |
| 并发 Concurrency | 双会话同时编辑、重复提交、处理中取消 |
| 声明 Claims | 挑战"实时""全部""私密""可撤销"类承诺文案 |
| 可观测性 Observability | 触发错误后有无可追踪信息（错误码、关联 ID、日志） |
| 依赖 Dependencies | 依赖服务异常时的降级与提示 |
| 平台 Platforms | 视口尺寸、浏览器、键盘操作、时钟/时区 |
| 历史 History | 用相邻输入重访近期修复过的地方（缺陷扎堆） |

### 4.2 测试章程（charter，可选）

较大范围探索时用一句话章程组织会话：`探索 [目标] 用 [资源/手段] 发现 [风险]`（例：探索订单创建流程，用超长与特殊字符输入，发现提交与列表渲染的健壮性风险）。一个章程一个时间盒，结束即小结。

### 4.3 回归测试范围（RCRCRC）

用户要求"回归"时按此圈定范围：**R**ecent 近期改动、**C**ore 核心功能、**R**isky 高风险区域、**C**onfiguration 敏感配置、**R**epaired 刚修复的缺陷（必须复测）、**C**hronic 惯犯区域（历史反复出问题的地方）。

## 6. 冒烟套件（规划时圈定）

从 P0 用例中圈定**最小核心冒烟集**（建议 ≤20 条或总量 15%，覆盖各 L1 模块至少一条主链路），用途：

- 新会话开工/续作恢复后先跑冒烟：全绿才继续全量，红则先停（环境或主链路已坏）；
- 缺陷修复后的快速回归：只跑冒烟 + 修复涉及模块，省预算；
- 冒烟集写入用例文档头部（用例编号清单），不随轮次随意变动。

## 7. 规划产出

- 用例文档（路径 B，经摘要展示非阻塞放行）或测试点清单（路径 A/C），含编号、标题、优先级、断言依据/预期、适用覆盖维度标记。
- 开工时在执行日报或环境说明中写明：本轮范围、选择的覆盖维度、不适用维度的理由。
- 覆盖度自查：执行结束前对照 `coverage-dimensions.md` 回看，未覆盖维度在报告中说明原因，不得静默遗漏。
