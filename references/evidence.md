# 证据三件套（evidence）

截图、错误日志、复现场景——任何结论必须挂这三类证据中的对应项；无证据不写结论。

## 1. 截图

### 1.1 目录与命名

- 统一目录：`<产出目录>/results/screenshots/`（与 artifacts-handoff.md §0 目录树一致；不要散落多个目录、不要建两套）。
- 命名：`<用例编号>-<序号>-<语义>.png`，例：`AUTH-005-1-403-page.png`、`ORD-036-2-upload-toast.png`。过程发现（无用例编号）用日期+序号：`20260908-1-dashboard-misaligned.png`。

### 1.2 何时必须截

| 场景 | 要求 |
| --- | --- |
| FAIL / BLOCKED | 必截：失败现场 + 错误提示出现的时刻 |
| FAIL / FLAKY | **四件套当场记齐**（artifacts-handoff.md §5）：截图 + 错误日志路径与关键报错摘要 + 复现步骤（或 BUG 单号）+ 已尝试定位方式；不允许"先记 FAIL 后补证据" |
| 涉及视觉断言的 PASS | 必截关键断言点（布局、徽章颜色、空态、图表） |
| 瞬态状态 | 前后双截（同调用内完成，见 execution-loop §2） |
| 过程发现异常 | 立即截当前状态 |

### 1.3 截图纪律

- 截图必须**实际查看**后才能作为证据；"截而不看"不算观察。
- 用例结果记录与 BUG 单中的截图一律写相对路径引用，与文字结论互链。
- 截图含密码输入框、token、敏感数据的，说明文字中脱敏（`***`），必要时裁剪。

## 2. 错误日志（console + 网络）

### 2.1 console 监听

- 开工即按 ZCode 内置浏览器的只读方式注册 console 监听（error + warning + 未捕获异常），全程收集，不违反黑盒原则。
- 工具不支持监听时，以页面可见错误表现为证据（错误文案、白屏、空白区域、资源加载失败占位、布局破坏），截图并注明"无法采集 console"，禁止注入 JS 监听绕过。

### 2.2 采集与落盘

| 场景 | 动作 |
| --- | --- |
| 用例 FAIL / BLOCKED | 必须落盘该用例的 console 日志与网络失败记录 |
| 用例 PASS 但过程中出现 error/warning | 同样落盘并开 BUG 单登记（待确认/缺陷类） |
| 怀疑静默失败（无 UI 反馈的失败请求） | 主动核对网络记录（4xx/5xx）与 console |

- 落盘位置：`<产出目录>/results/logs/<用例编号>/console.log` 与 `network.md`。
- `network.md` 每条失败请求记录：`时间 | method URL | status | 关键请求 body | 响应片段（脱敏）| 关联用例/操作步骤`。
- 最终报告单列"console 错误汇总"：每条注明发生时的操作步骤。

## 3. 复现场景（六要素）

每个缺陷/问题按六要素记录（缺陷类 BUG 单必填；环境问题/文档差异/待确认类可精简为入口 URL + 步骤摘要，见 issue-tracking.md §2）：

| 要素 | 内容 | 示例 |
| --- | --- | --- |
| ① 环境快照 | 前端/后端地址、版本或 commit、库名/环境标识 | `5173 / 3000 · main@a1b2c3d · app_e2e_20260908_test` |
| ② 账号 | 账号名与角色语义（密码脱敏） | `demo_member（普通成员角色，仅本项目可见）` |
| ③ 数据前置 | 依赖的数据及其状态（前缀、单据、状态机位置） | `E2E-DEMO-01 订单已支付；商品 SKU-xx 在售` |
| ④ 入口 URL | 直达页面的完整路径 | `/orders/{id}?tab=items` |
| ⑤ 操作步骤 | 编号步骤，精确到点击对象 | `1.点[发货] 2.填物流单号 3.点[确认]` |
| ⑥ 期望 vs 实际 + 概率 | 期望结果；实际结果；必现/偶发（复现 n/m 次） | `期望提示中文错误；实际英文原文；必现 3/3` |

- 偶发问题必须写明尝试次数与成功次数，并检查与环境（数据量、并发、缓存）的相关性。
- 缺陷修复后的**回归验证记录**追加在 BUG 单末尾：验证日期、验证账号与环境、复测步骤、结果（PASS/仍 FAIL）、证据路径。BUG 单只在回归 PASS 后才可闭环。

## 4. 证据互链

```
用例结果记录 ──引用──▶ 截图 / results/logs/<用例编号>/
     │
     └──缺陷/过程发现──▶ BUG 单（类别：缺陷/环境问题/文档差异/待确认；含证据与复现要点）
```

所有引用用相对路径；每张 BUG 单的"证据"至少给截图或日志之一。
