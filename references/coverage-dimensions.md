# UI/UX 覆盖维度自查矩阵（coverage-dimensions）

用途：规划时勾选本轮适用维度；执行结束前逐维度回看，未覆盖的必须说明原因。这是"不知道测什么/测全了没有"的答案清单。

## 1. 页面五态矩阵（每个列表/详情/面板/组件都逐态过一遍）

| 状态 | 检查点 |
| --- | --- |
| 空态 | 有无空态提示；文案是否指引用户下一步；空态≠错误态（无数据 vs 加载失败要可区分） |
| 加载态 | loading 指示、骨架屏；加载期间按钮是否防重复点击 |
| 错误态 | 请求失败有无友好提示；能否重试；错误文案是否本地化（禁止透出英文原始 error.message） |
| 内容态 | 数据正确性、排序、分页、计数（列表 count 与实际条数一致） |
| 部分加载 | 长列表分页/懒加载边界；部分区域失败不影响整页；骨架与真实内容切换无闪烁 |

## 2. 观察六维（每次页面状态变化后的观察清单）

| 维度 | 关注点 |
| --- | --- |
| 元素存在 | 关键元素存在且可见（含按钮、入口、角标、空态区） |
| 内容正确 | 文案、数字、状态徽章与预期一致（颜色语义、计数口径） |
| 状态变化 | URL、元素出现/消失、文本更新与操作匹配 |
| 布局遮挡 | 意外重叠、遮挡、截断、错位；区分合法浮层与渲染缺陷 |
| 渲染换行 | 超长文本溢出、异常换行、滚动容器、图片/图表渲染 |
| 视觉质量 | 对比度、颜色、排版、间距、对齐一致性 |

## 3. 数据类型攻击（输入类测试点生成器）

| 类型 | 攻击值 |
| --- | --- |
| 字符串 | 空、单个空格、多个空格、前导空格；255/256/1024+ 超长；带重音字符、中文、emoji；分隔符与特殊字符 `` ` ~ ! @ # $ % ^ & * ( ) _ + - = { } \| [ ] : " ; ' < > ? , . / ``；HTML/脚本注入串（如 `<script>`）、正则/URL 特殊字符 |
| 数字 | 0、负数、边界值（32767/32768、2147483647/2147483648）、小数/浮点精度、千分位写法、科学计数法 |
| 时间日期 | 无效日期（2月30日、9月31日）、闰年 2月29日、跨午夜/月末/年末、时区与夏令时、格式混用（dd/mm vs mm/dd）、过去/未来极端时间 |
| 文件 | 超大文件、空文件、错误扩展名、超长文件名、特殊字符文件名、同名覆盖 |
| 领域规则 | 违反业务约束的组合（如结束时间早于开始时间）、违反唯一性（重名/重复编码）、必填留空提交 |

## 4. 角色与权限矩阵（按代码实际角色定制，先判定适用性）

先按 test-case-generation.md §2"账号矩阵按需判定"确认适用性：代码无权限体系时本维度整体标"不适用"（依据：无角色/权限区分），仅保留"未登录"行为检查；有权限体系时按代码中**实际存在的角色**组织矩阵（从角色枚举/权限配置/路由守卫提取，不套用固定清单），对每个被测功能逐角色对比。
检查点：入口可见性（菜单/按钮隐藏 vs 禁用 vs 点击后 403）、直连 URL 访问（404/403 且不泄露数据）、API 层面拒绝（网络断言）、越权数据不出现在候选列表（如人员搜索只出现本项目成员）。

安全基线只读检查（SEC 类可自动化部分）：响应安全头经网络观察读取并对照基线（CSP、HSTS、X-Content-Type-Options、Set-Cookie 的 HttpOnly/Secure 属性）；页面文本与网络响应正则扫描敏感信息泄露（手机号、身份证号、token/JWT 形态、内部 IP/密钥形态）。深度攻击自动化（XSS 变异库、SQL 注入扫描）超出内置浏览器范围，标"人工/专项"。

## 5. 中断与并发

- 重复点击提交按钮（防抖/幂等）；请求挂起时继续操作；处理中取消。
- 后退/刷新后的状态一致性；表单未保存离开有无拦截。
- 会话过期后的行为（重新登录回到哪里）。
- 双标签页/双会话同时编辑同一条数据（row_version 冲突要有提示，禁止静默失败丢数据）。

多用户并发专项：双账号场景单独列用例——两账号同时编辑同一单据（冲突提示/自动刷新/数据不丢）；A 操作后 B 端联动（通知、待办、列表刷新的及时性）；可见性即时性（A 给 B 授权后 B 重新登录可见、移除后不可见）。能力限制：真双账号并发需要两个独立浏览器上下文，内置浏览器受限时降级为"同账号双标签"并注明，或标 `BLOCKED-tool` 转人工复核。

## 6. 交互反馈

- 每个写操作：成功反馈（toast/跳转/状态更新）、失败反馈（可读错误，非静默）、按钮 loading/禁用。
- 确认弹窗：文案与实际行为一致（弹窗说"恢复到处理中"，落库状态必须是处理中）。
- 通知/待办联动：主操作完成后，相关人的通知中心、待办列表是否同步；邮件/短信/Webhook 等浏览器外带外通道无法经内置浏览器验证，标"人工/外部通道验证"（不算 BLOCKED）。
- 快捷键与回车行为：搜索框 Enter 提交、编辑器保存按钮可见（不依赖隐蔽快捷键）。

## 7. 输入方式差异

键入 / 粘贴（含粘贴图片自动上传）/ 拖放 / 导入 —— 同一字段多种输入方式分别验证（缺陷常只出现在其中一种）。

## 8. 响应式与平台

- 关键页面 375px / 768px / 1440px 三档视口渲染（菜单折叠、表格横向滚动、弹窗不溢出）。
- 移动端外壳/入口（如有）：页面可达性、导航、权限抑制。
- 缩放 200% 下布局不破（可选）。

性能度量标准动作（PERF 类统一手段）：用只读 `performance.getEntriesByType('navigation' / 'resource')` 读取页面加载耗时、资源请求数、最大耗时资源，把数值记入用例结果；配合网络观察记录慢请求（>1s 可疑，>3s 必记）。断言写"数值 + 预期阈值"（如"首屏可交互 < 3s"），禁止"感觉卡顿"式结论；只读 API 不可用时以感知描述 + 截图记录并注明"未取得数值"。

## 9. 无障碍与键盘（只读 DOM 可检清单 + 视觉抽测）

只读 DOM 可检规则（逐页快扫）：`img` 有 alt（装饰图除外）；表单控件有关联 label；标题层级 h1→h6 不跳级；`html` 有 lang 属性；页面唯一 `main`；链接有可辨识文本（禁止裸"点击这里"）；必填项有标注。

视觉抽测项（代码检不了，走截图）：Tab 顺序合理、焦点可见、无焦点陷阱；弹窗可 Esc 关闭且焦点管理正确；错误不只靠颜色区分；对比度可读。

## 10. 导航与深链

菜单结构与顺序、面包屑、重定向规则；收藏 URL 直达、登出后访问书签、带参数深链（通知/待办跳转目标正确）、未保存离开拦截。

## 11. 一致性巡检（顺带发现的高发区）

同语义文案全站一致（按钮/状态/提示词）；状态徽章颜色语义一致；同类列表列结构一致；日期/数字格式统一；中英混杂；错别字。

## 12. 计数与统计口径

列表汇总 chips、KPI 卡、统计下钻与列表筛选条件保持一致（筛选后 KPI 必须跟着变）；全局计数用"差值断言"（操作前后对比），网络测试环境（多人共用）不做绝对值断言。

## 13. 使用方法

1. 规划阶段：逐维度判断适用性，不适用的写明理由（如"无文件上传功能"）。
2. 执行阶段：每个功能区至少把 §1 五态和 §2 六维过一遍；§3-§12 按功能风险抽测。
3. 收尾阶段：回看本矩阵，未覆盖维度在执行报告"覆盖度"一节说明原因。

## 14. 国际化与本地化（i18n/L10n，按产品市场判断适用性）

- 语言切换入口（如有）：切换后文案、布局、已输入数据完整保留；
- 本地化格式：日期（dd/mm vs mm/dd）、数字千分位与小数符、货币符号按 locale 正确渲染；
- 时区：跨时区用户看到的时间显示正确（与数据攻击 §3 的时区项联动）；
- 翻译完整性与术语一致：无中英混杂、无未翻译占位符（与一致性巡检 §11 联动）；
- RTL 预留：仅当产品声明支持 RTL 语言时检查镜像布局。
